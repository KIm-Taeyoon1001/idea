# IDEA-002 — DeductLens

> **한 줄 설명:** 대형 유통사·플랫폼에 납품하는 소규모 공급업체가 엑셀 정산 내역만으로 반복 차감의 원인을 찾아 다음 출하에서 같은 손실을 줄이도록 돕는 경량 분석 SaaS.

**상태:** 초기 사업 가설 — 고객 인터뷰 전  
**시장 범위:** 한국 소규모 납품업체를 시작점으로 검증하고, 이후 글로벌 리테일 공급업체로 확장  
**핵심 원칙:** 차감액을 대신 회수해 주는 서비스가 아니라, 반복 손실을 발견하고 예방하는 의사결정 도구

---

## 1. 발견한 불편함

대형 유통사나 플랫폼에 제품을 납품하는 작은 업체는 정산 과정에서 배송 지연, 수량 차이, 라벨 오류, 서류 누락, 가격 불일치 등의 사유로 대금 일부가 차감될 수 있다.

문제는 차감이 발생한 뒤 담당자가 다음 자료를 따로 확인해야 한다는 점이다.

- 유통사 정산서 또는 차감 내역
- 발주서와 납품서
- 송장·운송장 및 배송 증빙
- 출하 시점의 라벨·포장 기록
- 담당자가 주고받은 이메일과 메모

전담 분석 인력이 없는 업체에서는 차감 건을 하나씩 처리하는 데 그치고, 같은 원인이 반복되어도 어느 거래처·품목·물류센터·업무 단계에서 손실이 발생하는지 파악하기 어렵다는 가설을 세운다.

**검증해야 할 핵심 질문:** 실제 소규모 납품업체가 차감 사유를 월별로 분석하지 못해 반복 손실을 겪고 있는가? 그 손실 규모가 월 구독료보다 큰가?

## 2. 문제의 근본 원인

1. 정산 데이터가 거래처마다 다른 엑셀·CSV·PDF 형식으로 도착한다.
2. 차감 코드와 설명이 거래처별로 달라 단순 합산만으로 원인을 비교하기 어렵다.
3. 차감 건과 당시 출하·문서·담당자 기록이 서로 다른 폴더에 흩어져 있다.
4. 담당자는 당장 정산 건을 처리하느라 장기적인 반복 패턴을 분석할 시간이 부족하다.
5. 원인을 알아도 현장 작업자가 실행할 수 있는 예방 조치로 연결되지 않는다.

이 원인들은 현재 확인된 보편적 사실이 아니라, 고객 인터뷰와 실제 정산 파일로 검증할 가설이다.

### 경쟁 조사 결론

이 문제 영역에는 이미 경쟁 제품과 서비스가 존재한다. 따라서 '차감 관리 SaaS' 전체를 새로운 시장이라고 주장하지 않는다.

DeductLens의 차별화 가설은 다음과 같이 제한한다.

- 대기업용 ERP·EDI 연결 없이 엑셀·CSV 업로드만으로 시작한다.
- 차감 건을 대신 제출하거나 회수하는 것이 아니라, 반복 손실의 패턴을 보여준다.
- 거래처·품목·물류센터·차감 코드·기간을 조합해 원인 집중도를 분석한다.
- 각 패턴에 대해 현장에서 실행할 수 있는 예방 체크리스트를 만든다.
- 소규모 업체가 부담 없이 시험할 수 있는 낮은 가격과 빠른 초기 설정을 지향한다.

이 차별성이 실제 시장에서 충분한지는 아직 입증되지 않았다. 경쟁 서비스가 이미 같은 기능과 가격으로 소규모 업체를 잘 지원한다면 아이디어를 폐기하거나 방향을 바꾼다.

## 4. 제안 제품

### DeductLens — 반복 차감 손실 분석기

사용자가 정산 내역 파일을 업로드하면 거래처별 차감 사유와 금액을 정규화하고, 반복되는 손실 패턴을 찾아 보여주는 웹 SaaS다.

예시 결과:

- 최근 90일 차감 합계와 월별 추이
- 차감 사유별 금액 및 발생 건수
- 특정 거래처·품목·물류센터에 집중된 차감
- 반복적으로 발생하는 상위 원인
- 원인별 확인이 필요한 증빙 목록
- 다음 출하 전에 확인할 예방 체크리스트

AI는 사유 텍스트 분류와 요약을 보조한다. 금액 계산과 집계는 결정론적 로직으로 수행하고, 원본 행과 계산 근거를 항상 확인할 수 있게 한다.

## 5. 핵심 사용 흐름

1. 사용자가 정산서 CSV 또는 XLSX를 업로드한다.
2. 서비스가 열 이름과 차감 사유를 분석해 표준 항목으로 매핑한다.
3. 매핑이 불확실한 항목은 사용자가 직접 확인한다.
4. 차감 금액·건수·기간·거래처별 패턴을 집계한다.
5. 반복 원인과 관련된 원본 행을 근거로 제시한다.
6. 사용자가 예방 조치를 선택하고 다음 출하 체크리스트로 저장한다.
7. 다음 달 파일을 추가하면 이전 기간과 비교한다.

## 6. 목표 고객과 사용해야 하는 이유

### 1차 고객

- 대형 유통사·온라인 플랫폼에 납품하는 소규모 제조사
- 여러 거래처에 납품하지만 전담 정산 분석 인력이 없는 공급업체
- 월별 정산 파일을 엑셀로 관리하는 소규모 브랜드·도매업체

### 고객이 사용할 이유

- 반복 손실이 어디에서 발생하는지 빠르게 파악한다.
- 매달 수작업으로 정산 파일을 합치고 분류하는 시간을 줄인다.
- 거래처별 문제를 추측이 아니라 데이터로 확인한다.
- 다음 출하 때 현장 담당자가 확인할 항목을 구체화한다.

## 7. 수익 모델 가설

가격은 시장에서 확인된 사실이 아니라 초기 검증용 가설이다.

| 플랜 | 월 가격 가설 | 범위 |
|---|---:|---|
| Starter | 무료 | 월 1개 파일, 기본 집계 |
| Solo | ₩29,000 | 월별 파일 업로드, 기간 비교, 기본 리포트 |
| Business | ₩79,000 | 여러 거래처·품목 분석, 체크리스트, 팀 공유 |
| Partner | 별도 협의 | 회계·물류 대행사 다수 고객 관리 |

핵심 수익 지표는 유료 고객당 월 매출, 고객별 분석 빈도, 유료 전환율, 고객 유지율, 파일 처리 비용이다.

성공 수수료나 차감 회수 대행 수수료는 초기 제품 범위에 넣지 않는다.

## 8. MVP 개발 범위

### 반드시 구현할 기능

1. CSV·XLSX 업로드
2. 열 이름 자동 인식과 수동 매핑
3. 거래처별 차감 사유 표준화
4. 차감액·건수·기간별 집계
5. 반복 원인 상위 항목과 원본 행 연결
6. 월별 비교 리포트 PDF 또는 CSV 내보내기

### MVP에서 제외할 기능

- 유통사 포털 자동 로그인 및 제출
- ERP·EDI 양방향 통합
- 자동 이의제기 또는 법률 판단
- 현장 카메라·센서 연동
- AI가 검증 없이 차감 사유를 확정하는 기능

## 9. 기술 아키텍처 제안

- Frontend: Next.js + TypeScript
- UI: Tailwind CSS
- Backend: Cloudflare Workers
- Database: Supabase PostgreSQL
- File storage: Supabase Storage 또는 R2
- Spreadsheet parsing: SheetJS 또는 서버 측 파서
- Analytics: SQL 집계 및 규칙 기반 분류
- Optional AI: 불규칙한 차감 설명의 분류·요약
- Auth: Supabase Auth

### 데이터 신뢰성 원칙

- 원본 파일과 정규화 결과의 연결을 보존한다.
- 금액·수량 집계는 AI가 아니라 코드로 계산한다.
- 통화·세금·부호·중복 행을 명시적으로 처리한다.
- 분류가 불확실한 행은 '미분류'로 남긴다.
- 고객 데이터는 테넌트 단위로 분리하고 업로드 파일의 보존·삭제 정책을 제공한다.

## 10. 고객 확보 전략

1. 소규모 제조·도매업체의 대표 및 경리·영업관리 담당자 인터뷰
2. 실제 데이터가 아닌 합성 예시 파일로 무료 데모 제공
3. 고객 동의를 받은 비식별 샘플 파일로 분석 정확도 검증
4. 제조업 협회·지역 산업단지·소상공인 네트워크를 통한 파일럿 모집
5. 회계·물류 대행사와의 소개 파트너십 검토

초기에는 광고보다 직접 인터뷰와 파일럿으로 문제의 강도를 검증한다.

## 11. 초기 비용 및 운영 리스크

### 비용 가설

- MVP: 기존 무료·저가 개발 도구를 활용해 개발비 최소화
- 초기 인프라: 무료 구간에서 시작하되 실제 파일 용량·처리량에 따라 비용 확인
- AI 비용: 필수 경로가 아닌 선택 기능으로 제한
- 주요 변동비: 파일 저장, 파싱, AI 호출, 이메일 발송

정확한 월 운영비는 파일 크기와 고객 사용량을 측정한 후 산정한다.

### 리스크와 대응

- **고객 데이터 민감성:** 실제 정산 파일에는 거래처·가격·계좌 등 민감한 정보가 있을 수 있다. 최소 수집, 암호화, 접근 통제, 삭제 기능을 기본으로 한다.
- **파일 형식 차이:** 거래처별 양식에 따라 파싱 실패가 발생할 수 있으므로 수동 열 매핑과 오류 보고를 제공한다.
- **잘못된 원인 분류:** AI 분류는 제안으로만 표시하고 사용자가 수정할 수 있게 한다.
- **시장 경쟁:** 차감 관리·회수 플랫폼이 이미 있으므로 고객 규모와 도입 비용에서 실제 빈틈이 있는지 검증한다.
- **지불 의사 부족:** 차감액이 작거나 발생 빈도가 낮은 고객은 유료 고객이 아닐 수 있다. 손실 규모와 반복 빈도를 기준으로 고객군을 좁힌다.

### 12~14일: 지불 의사 검증

- ₩29,000 및 ₩79,000 가격 가설 제시

기준을 충족하지 못하면 시장을 더 좁히거나 아이디어를 폐기한다.

**결론:** DeductLens는 경쟁이 없는 아이디어가 아니다. 다만 기존의 기업용 차감 회수·정산 자동화와 달리, 정산 엑셀만 가진 소규모 납품업체가 반복 손실을 분석하고 예방하는 저비용 도구라는 틈새 가설을 검증할 가치는 있다. 고객 인터뷰에서 실제 손실과 지불 의사가 확인되지 않으면 개발하지 않는다.
