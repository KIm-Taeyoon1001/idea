# IDEA-003 — LiningProof

> **한 줄 설명:** 내화물 시공 전문업체가 현장에서 발생하는 자재 Lot, 작업자, 시공 검사, 승인된 건조 기록과 사진을 하나의 작업 이력으로 연결하고 고객 제출용 품질 문서를 자동으로 묶도록 돕는 현장 품질 증빙 SaaS.

**상태:** 초기 사업 가설 — 고객 인터뷰 및 유료 파일럿 전  
**조사 기준일:** 2026-11-09  
**초기 고객 가설:** 내화물 시공·보수 전문업체 및 내화물 제조사의 현장 서비스 조직  
**제품 범위:** 시공 기록·증빙 수집·문서화. 설계, 시공 지시, 건조 스케줄 산출, 안전 판단 또는 품질 인증을 대체하지 않는다.

---

## 1. 발견한 불편함

내화물 라이닝 시공은 자재 입고부터 시공, 검사, 양생·건조, 인수인계까지 여러 단계의 기록이 발생한다. 발주처의 시방서와 프로젝트별 검사·시험 계획에 따라 자재 식별, 작업자, 장비, 혼합·시공 조건, 검사 결과, 부적합 사항, 사진, 건조 기록 등을 남겨야 할 수 있다.

API의 공개 표준 소개는 API STD 936이 모놀리식 내화물 라이닝의 설치 품질관리 절차와 자재·장비·인력의 자격, 적용 품질 모니터링 및 검사 책임을 다룬다고 설명한다. API 936 인증 안내도 설치·검사·시험·보수 관련 지식을 범위에 포함한다.

현장 기록이 종이 양식, 엑셀, 휴대전화 사진, 온도 기록 파일, 이메일로 나뉘면 다음 문제가 생길 수 있다는 가설을 세운다.

- 사진과 측정값이 어느 설비·구역·작업일·자재 Lot에 해당하는지 다시 확인해야 한다.
- 작업 중에는 기록이 누락되고, 공사 종료 후 사무실에서 보고서를 재구성할 수 있다.
- 발주처별 양식과 승인 절차가 달라 같은 내용을 여러 문서에 반복 입력할 수 있다.
- 하자나 품질 이슈가 발생했을 때 당시의 자재·작업·검사·건조 기록을 한 번에 연결하기 어렵다.

이 문제가 모든 내화물 시공업체에서 빈번하게 발생한다는 근거는 아직 없다. 실제 프로젝트의 기록 작성 시간과 누락 사례를 인터뷰로 확인해야 한다.

## 2. 문제의 근본 원인

1. **기록 단위가 분리됨:** 프로젝트, 설비, 라이닝 구역, 자재 Lot, 작업조, 검사 결과가 서로 다른 파일이나 양식에 저장된다.
2. **현장 입력 부담:** 작업자는 시공에 집중해야 하므로 사무실에서 나중에 기록을 정리하는 방식이 생길 수 있다.
3. **발주처별 양식 차이:** 고객별 실행계획서, 검사·시험 계획, 제출 문서 형식이 다르다.
4. **증빙과 작업의 연결 부족:** 사진·온도 파일·시험 성적서가 작업 단계 및 해당 구역과 자동으로 연결되지 않는다.
5. **프로젝트 종료 후 재구성:** 공정 중 수집한 정보가 고객 인수인계용 문서로 곧바로 정리되지 않는다.

위 내용은 제품 설계 가설이다. 고객이 이미 ERP, QMS 또는 자체 양식으로 문제를 충분히 해결하고 있다면 제품의 필요성이 낮을 수 있다.

### 경쟁 조사 결론

내화물 관리 소프트웨어와 범용 현장 작업 앱이 이미 존재한다. 따라서 '내화물 기록 관리' 전체를 새로운 시장이라고 주장하지 않는다.

LiningProof가 검증하려는 좁은 틈새는 **플랜트 운영자의 라이닝 수명 관리가 아니라, 내화물 시공업체가 프로젝트별 승인 문서에 맞춰 현장 증빙을 수집하고 고객 제출용 준공·품질 패키지를 만드는 과정**이다.

다음 상황이면 차별성이 약하다.

- 고객이 기존 CMMS/QMS 또는 범용 현장 앱의 양식 기능으로 충분히 해결하고 있다.
- 프로젝트별 문서 제출에 드는 시간이 적어 구독료를 정당화하지 못한다.
- 발주처가 디지털 증빙을 받지 않고 종이·자체 포털만 허용한다.
- 이미 Reframanager 또는 유사 시스템을 시공업체까지 포함해 사용하고 있다.

이 경우 개발을 중단하거나 기존 시스템용 내보내기·연동 도구로 범위를 바꿔야 한다.

## 4. 제안 제품

### LiningProof — Refractory Job Evidence Workspace

프로젝트의 승인된 실행계획과 검사·시험 계획을 기준으로 현장 기록 항목을 구성하고, 각 기록을 설비·구역·자재 Lot·작업일·작업조에 연결한다.

핵심 기능 가설:

1. **프로젝트별 기록 템플릿:** 고객이 승인한 양식과 검사 항목을 등록하고 필수 증빙 목록으로 구성한다.
2. **현장 오프라인 입력:** 네트워크가 불안정한 현장에서도 작업 기록과 사진을 저장하고 연결 복구 후 동기화한다.
3. **자재 Lot 연결:** 포장 라벨의 QR 또는 바코드를 읽어 자재 식별번호와 사용 위치를 연결한다.
4. **검사·시험 기록:** 담당자가 입력한 측정값, 시험 결과, 샘플 식별정보, 사진과 승인 이력을 기록한다.
5. **부적합·변경 이력:** 현장 편차와 시정 조치, 발주처 승인 여부를 원본 기록과 함께 보존한다.
6. **건조 기록 수집:** 고객이 승인한 건조 절차와 실제 측정 파일 또는 기록을 연결한다. 제품이 건조 절차를 생성하거나 안전성을 판정하지 않는다.
7. **인수인계 패키지:** 프로젝트 종료 시 승인된 템플릿에 맞춰 사진 목록, 기록표, 첨부 파일과 누락 항목을 PDF/ZIP으로 정리한다.

## 5. 핵심 사용 흐름

1. 사무실 담당자가 프로젝트, 고객, 설비와 작업 구역을 등록한다.
2. 고객이 승인한 실행계획·검사 항목·제출 양식을 업로드하고 필수 기록을 설정한다.
3. 현장 작업자가 모바일 화면에서 배정된 작업을 선택한다.
4. 자재 Lot, 작업조, 장비, 작업 단계, 측정값과 사진을 기록한다.
5. 검사자와 책임자가 실제 결과를 검토하고 승인 또는 보완 요청을 남긴다.
6. 승인된 건조 계획과 실제 기록 파일을 해당 구역·작업 이력에 연결한다.
7. 프로젝트 종료 시 문서 누락 목록을 확인하고 고객 제출용 패키지를 내보낸다.
8. 이후 보수·하자 사례가 발생하면 기존 프로젝트와 관련 Lot 및 작업 기록을 검색한다.

## 6. 목표 고객과 사용 이유

### 1차 고객

- 산업용 보일러·로·가마·용해로 등의 내화물 라이닝 시공 및 보수 전문업체
- 프로젝트마다 다른 발주처 양식과 품질 문서를 제출하는 하도급업체
- 내화물 제조 후 현장 시공·보수 서비스를 함께 제공하는 기업의 서비스 조직

### 사용해야 할 이유

- 작업 중에 기록을 남겨 종료 후 문서를 재구성하는 시간을 줄일 수 있다.
- 자재 Lot, 작업 구역, 작업자, 검사 결과를 연결해 하자 조사에 필요한 자료를 찾기 쉬워진다.
- 고객 제출 문서에서 빠진 항목을 프로젝트 종료 전에 확인할 수 있다.
- 숙련 작업자의 개인 파일과 기억에 의존하는 업무 이력을 회사의 기록으로 남길 수 있다.

이 가치는 인터뷰와 실제 프로젝트 파일럿으로 확인해야 하며, 품질 향상이나 사고 감소를 보장하지 않는다.

초기에는 프로젝트형 유료 파일럿으로 구매 장벽을 낮추고, 반복 사용이 확인되면 팀 구독으로 전환한다. 고객별 템플릿 설정·초기 데이터 이관은 별도 온보딩 비용으로 검토한다.

## 8. MVP 개발 범위

### 첫 파일럿에 반드시 필요한 기능

1. 프로젝트·설비·구역·작업조 등록
2. 고객 승인 양식에 기반한 필수 입력 항목 설정
3. 모바일 웹(PWA) 오프라인 기록 및 동기화
4. 자재 Lot 번호 수동 입력 또는 QR 스캔
5. 사진·문서 첨부와 시간 기록
6. 검사 결과·부적합·승인 이력
7. 프로젝트별 누락 항목 확인
8. PDF 요약 보고서와 원본 증빙 ZIP 내보내기

### 초기 버전에서 제외할 기능

- 건조 스케줄 또는 시공 조건의 자동 생성·추천
- 온도 센서·PLC·SCADA 직접 제어
- AI에 의한 합격·불합격 판정
- 자동 품질 인증 또는 API 936 준수 인증 주장
- 플랜트 전체의 마모 예측·정비 일정 관리
- ERP·CMMS 양방향 통합

## 9. 기술 구현 제안

- Frontend: Next.js + TypeScript
- Mobile: PWA, IndexedDB 기반 오프라인 입력 큐
- Backend: Supabase PostgreSQL + Auth
- File storage: Cloudflare R2 또는 Supabase Storage
- Sync: 변경 이벤트 ID와 충돌 검토 화면을 갖춘 재시도 가능한 동기화
- Reports: 서버 측 PDF 생성 및 원본 파일 ZIP
- QR: 자재 Lot·설비 구역 식별용 QR 코드
- Optional AI: 업로드된 고객 양식에서 필드 후보를 추출하되 관리자가 검토·확정

### 데이터 신뢰성 원칙

- 입력값과 원본 첨부 파일을 연결하고 수정 이력을 남긴다.
- AI가 추출한 값은 승인 전까지 확정 기록으로 취급하지 않는다.
- 측정값의 단위·측정 위치·측정 시각을 함께 저장한다.
- 고객 승인 절차와 책임자를 제품이 대신 결정하지 않는다.
- 오프라인 동기화 충돌은 자동으로 덮어쓰지 않고 사용자에게 검토를 요청한다.

## 10. 고객 확보 전략

1. 내화물 시공·보수업체 10곳과 QA/QC 담당자 인터뷰
2. API 936 교육·검사 관련 네트워크와 내화물 산업 협회·전시회에서 문제 사례 수집
3. 고객이 제공한 비식별 프로젝트 양식으로 샘플 기록 화면 제작
4. 한 업체의 실제 프로젝트 한 건에서 종이·엑셀 방식과 병행하는 유료 파일럿 제안
5. 파일럿 결과를 바탕으로 문서 작성 시간, 누락 건수, 현장 입력률을 비교
6. 성과가 확인되면 내화물 제조사의 현장 서비스 조직과 검사 전문업체로 확장

초기 고객 획득은 온라인 광고보다 업계 관계자 소개와 직접 인터뷰가 적합할 가능성이 높다. 다만 산업 분야 특성상 영업 주기가 길고 신뢰 확보가 필요하다.

## 11. 초기 비용 및 운영 리스크

### 초기 비용 가설

- MVP 개발: 기존 웹·클라우드 도구를 활용하면 현금 지출은 낮출 수 있지만, 오프라인 동기화와 현장 테스트에 개발 시간이 필요하다.
- 인프라: 소규모 파일럿은 무료 또는 저가 구간에서 시작할 수 있으나 사진·영상·대용량 측정 파일 저장량에 따라 비용이 증가한다.
- 도입 비용: 고객별 양식 구성, 현장 교육, 기존 기록 이관에 운영 시간이 들 수 있다.
- 주요 비용 항목: 파일 저장·전송, PDF 생성, 백업, 보안 관리, 현장 지원, 고객별 설정.

실제 비용은 파일럿 사용량을 측정한 뒤 산정한다. 초기 인프라 비용보다 현장 온보딩과 맞춤 설정이 더 큰 비용이 될 수 있다.

### 리스크와 대응

- **안전·기술 책임:** 소프트웨어가 시공 또는 건조 절차를 추천하거나 안전성을 판정하지 않는다. 고객이 승인한 절차와 실제 기록을 보존하는 도구로 한정한다.
- **표준·고객별 차이:** API 표준만으로 모든 프로젝트 요구사항을 자동 결정하지 않는다. 최신 표준과 발주처 승인 문서를 사람이 확인하고 템플릿을 설정한다.
- **현장 네트워크:** 오프라인 입력과 동기화 충돌 검토를 제공한다.
- **작업자 도입 저항:** 필수 입력만 남기고 사진·QR·음성 메모 등 빠른 입력 방식을 검증한다.
- **문서 위변조·분쟁:** 수정 이력과 원본을 보존하되, 제품 기록이 법적 증명력이나 인증을 자동 보장한다고 주장하지 않는다.
- **기존 시스템과 중복:** 기존 QMS/CMMS/범용 현장 앱의 설정으로 충분하다면 고객은 별도 SaaS를 구매하지 않을 수 있다.
- **고객 데이터 보안:** 설비 도면, 작업 조건, 고객사 정보는 민감할 수 있다. 최소 수집, 권한 분리, 암호화, 보존·삭제 정책이 필요하다.

## 12. 21일 시장 검증 계획

### 1~5일: 문제 확인

- 시공업체·제조사 서비스 조직·검사 담당자 10명 인터뷰
- 최근 프로젝트에서 고객 제출 문서를 누가, 어떤 파일로, 얼마나 오래 준비하는지 확인
- 실제 누락·재작성·하자 조사 사례가 있었는지 질문

### 6~10일: 양식 분석

- 동의를 받은 비식별 실행계획·검사 양식·준공 패키지 샘플 3건 확보
- 프로젝트마다 공통 항목과 고객별 차이를 분리
- 기존 ERP/QMS/현장 앱으로 해결 가능한 범위를 확인

### 11~16일: 프로토타입

- 프로젝트 생성, 모바일 기록, 사진 첨부, Lot 연결, 누락 확인, PDF 출력 구현
- 한 개 고객의 승인된 양식을 기준으로만 작동하도록 범위를 제한

### 17~21일: 현장 파일럿 및 지불 의사

- 실제 프로젝트 한 건에서 기존 방식과 병행 테스트
- 작업자 입력률, 기록 누락, 보고서 재작성 시간 측정
- 프로젝트당 유료 사용 의향과 다음 프로젝트 재사용 의향 확인

### 진행 기준 가설

- 인터뷰 10명 중 5명 이상이 문서 취합·증빙 누락 문제를 반복적으로 경험
- 3곳 이상이 비식별 양식 또는 파일럿 참여에 동의
- 1곳 이상이 프로젝트 단위 유료 파일럿에 동의
- 현장 기록 완료율이 기존 방식보다 개선되고, 보고서 재작성 시간이 감소

기준을 충족하지 못하면 범용 현장 앱과의 차별성이 부족한 것으로 보고 개발을 중단하거나 기존 시스템 연동으로 방향을 바꾼다.

## 13. 핵심 성과 지표

- 필수 기록 항목의 현장 완료율
- 프로젝트 종료 시 누락된 증빙 수
- 고객 제출 패키지 작성에 걸리는 시간
- 현장 작업자 주간 활성률
- 사진·측정값·Lot 연결 오류율
- 프로젝트별 재사용률
- 유료 파일럿 전환율과 다음 프로젝트 재구매율
- 고객별 온보딩 시간과 지원 비용

## 14. 사업성 평가

| 평가 항목 | 현재 판단 |
|---|---|
| 문제의 실재 가능성 | 중간 — 표준상 기록 요구는 확인했으나 업체별 수작업 부담은 미검증 |
| 지불 의사 | 미검증 |
| 경쟁 강도 | 중간~높음 — 내화물 관리 시스템과 범용 현장 앱이 존재 |
| 기술적 MVP 난이도 | 중간 — 오프라인 동기화와 문서 패키징이 핵심 난제 |
| 초기 현금 비용 | 낮음~중간 — 현장 온보딩과 지원 비용은 별도 |
| 고객 획득 난이도 | 높음 — 전문 산업의 신뢰 기반 B2B 영업 필요 |
| 확장성 | 중간 — 내화물 시공에서 산업용 단열·라이닝·보수 계약업체로 확장 가능성 |
| 차별성 | 미검증 — 시공업체의 프로젝트 증빙 흐름이 기존 도구보다 실제로 편한지 확인 필요 |
| 현재 결정 | 유료 파일럿 전제의 조건부 검증 |

**결론:** LiningProof는 내화물 시공업체의 프로젝트별 품질 증빙과 고객 인수인계 문서화에 집중한다. 플랜트의 라이닝 수명 예측이나 일반적인 현장 작업 관리 제품을 복제하지 않는 것이 핵심이다. 실제 프로젝트에서 기록 재작성 시간이 크고, 기존 시스템으로 해결되지 않으며, 업체가 프로젝트 단위 비용을 지불할 때만 개발을 계속한다.
