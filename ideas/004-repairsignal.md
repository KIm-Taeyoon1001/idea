# IDEA-004 — RepairSignal

> **한 줄 설명:** 독립 수리점의 수리·부품 조달 기록을 익명화해, 가전 제조사와 부품 유통사가 실제 고장 유형·부품 부족·수리 지연을 파악하도록 돕는 수리 데이터 인텔리전스 SaaS.

**상태:** 초기 사업 가설 — 고객 인터뷰 및 유료 파일럿 전  
**조사 기준일:** 2026-11-10  
**초기 시장 가설:** 진공청소기·커피머신 등 소형 가전의 독립 수리점과 부품 유통사  
**핵심 원칙:** 기존 수리점 POS를 대체하지 않고, 각 업체에 흩어진 기록을 동의하에 표준화·집계한다.

---

## 1. 발견한 불편함

독립 수리점은 어떤 제품이 자주 고장 나는지, 어떤 부품을 구하지 못해 수리가 지연되거나 포기되는지, 특정 모델의 수리비와 조달 기간이 어느 정도인지 매일 경험한다. 그러나 이 정보는 업체별 작업 티켓, 재고 프로그램, 엑셀, 종이 기록에 분산되어 있다.

그 결과 다음과 같은 정보 비대칭이 생길 수 있다.

- 수리점은 자주 필요한 부품을 경험적으로만 판단하고, 지역·모델별 수요를 다른 업체와 비교하기 어렵다.
- 부품 유통사는 실제 수리 현장에서 어떤 부품이 부족한지, 어떤 모델에서 미충족 수요가 생기는지 알기 어렵다.
- 제조사는 공식 서비스망 밖에서 반복되는 고장 유형과 부품 조달 문제를 충분히 파악하지 못할 수 있다.
- 수리 실패 원인이 기술 부족인지, 부품 미공급인지, 수리비 문제인지 구조화되지 않아 개선 우선순위를 정하기 어렵다.

### 문제의 규모를 보여주는 인접 데이터

Repair Café International의 2026년 글로벌 조사 결과는 30개국 946개 응답을 바탕으로 약 60,000개 행사, 연간 160만 개 이상의 반입 물품, 약 89,000명의 자원봉사자 규모를 제시한다. 응답 단체의 80% 이상은 수리 정보를 종이에 기록하고, 45%는 나중에 전자 시스템에 입력한다고 답했다. 이는 지역사회 수리 활동에서조차 기록의 디지털화가 충분하지 않을 수 있음을 보여준다. 다만 이 수치는 **상업 수리점 시장의 규모나 구매 의사를 직접 증명하지 않는다.**

Open Repair Alliance는 2024년 공개 보고서에서 31개국 1,158개 그룹의 수리 시도 200,000건 이상을 다루었다. 공통 데이터 표준을 통해 여러 단체의 기록을 결합할 수 있다는 점은 데이터 네트워크의 가능성을 보여준다.

특히 The Restart Project는 공개 데이터에서 제품 모델, 부품 필요 여부, 후속 조치 관련 일부 필드를 제외한다고 설명한다. 일부 데이터가 불완전하고 상업적 가치가 있을 수 있기 때문이다. 이 지점은 RepairSignal이 검증할 수 있는 데이터 공백이다. 다만 공개되지 않는다는 사실이 곧바로 유료 수요를 의미하지는 않는다.

## 2. 문제의 근본 원인

1. **데이터가 업체별로 고립됨:** 작업 티켓과 재고 데이터는 개별 수리점 운영을 위해 저장되고, 업계 전체를 비교할 수 있는 공통 형식으로 모이지 않는다.
2. **부품 부족 사유가 정형화되지 않음:** '부품 없음', '단종', '납기 지연', '가격 과다', '호환성 확인 불가'가 메모에만 남을 수 있다.
3. **모델 정보와 수리 결과의 연결이 약함:** 브랜드·모델·고장 증상·사용 부품·수리 성공 여부가 서로 다른 항목에 기록될 수 있다.
4. **기존 시스템의 목적이 다름:** 수리점 POS는 작업·결제·재고·고객 응대에 초점을 둔다. 다른 업체의 익명화된 수리 데이터를 집계하는 기능은 별도 문제다.
5. **데이터 공유에 대한 신뢰가 부족함:** 수리점은 고객 정보, 거래처, 가격, 영업 노하우가 경쟁사나 제조사에 노출될 것을 우려할 수 있다.

이 원인들은 공개 자료와 제품 기능을 바탕으로 세운 가설이다. 실제 수리점 데이터 샘플과 인터뷰를 통해 확인해야 한다.

### 경쟁 조사 결론

수리점 관리 소프트웨어, 커뮤니티 수리 데이터베이스, 자동차 수리 분석 제품, 부품 판매 플랫폼이 이미 존재한다. 따라서 '수리 데이터 분석' 전체가 새로운 시장이라고 주장하지 않는다.

RepairSignal의 좁은 차별화 가설은 **독립 가전 수리점의 동의받은 작업 기록에서 부품 미공급·조달 기간·수리 포기 데이터를 구조화하고, 이를 여러 업체 단위로 익명 집계해 제조사와 부품 유통사에 제공하는 것**이다.

공개 자료만으로 동일한 제품이 전혀 없다고 단정할 수 없다. 특히 기존 수리 POS나 유통사의 비공개 내부 분석 기능은 확인하지 못했다. 실제 데모·고객 인터뷰에서 중복 기능을 확인해야 한다.

## 4. 제안 제품

### RepairSignal — Repair Market Intelligence

RepairSignal은 독립 수리점이 보유한 수리 이력 파일을 안전하게 가져와 표준화하고, 개인·매장 식별 정보를 제거한 집계 데이터로 시장 신호를 제공한다.

핵심 기능 가설:

1. **수리 기록 가져오기:** CSV·XLSX 업로드로 시작한다. 초기에는 특정 POS의 실시간 API 연동을 전제하지 않는다.
2. **데이터 표준화:** 제품 카테고리, 브랜드, 모델, 고장 유형, 필요 부품, 부품 조달 상태, 대기 기간, 수리 결과를 공통 필드로 정리한다.
3. **부품 부족 신호:** 부품 미확보로 수리가 지연·중단된 빈도와 추세를 집계한다.
4. **모델별 수리 패턴:** 제품 모델과 고장 유형별 수리 시도·성공·미완료 비율을 보여준다. 표본이 부족하면 수치를 숨기거나 신뢰도가 낮다고 표시한다.
5. **유통사 대시보드:** 지역·기간·제품군별 미충족 수요와 반복적인 조달 지연을 확인한다.
6. **제조사 리포트:** 반복 고장, 부품 부족, 수리 지연과 같은 신호를 근거 레코드 수와 함께 제공한다.
7. **데이터 내보내기:** 수리점은 자신의 원본 및 표준화 데이터를 내려받을 수 있다.

AI는 자유 서술형 고장 메모의 분류 후보를 제시하는 보조 기능으로만 사용한다. 모델명, 부품번호, 수리 결과와 집계 수치는 규칙 기반 검증 및 사용자 확인을 거친다.

## 5. 핵심 사용 흐름

1. 수리점이 데이터 제공 범위와 익명화·집계 목적에 동의한다.
2. CSV 또는 XLSX 작업 이력을 업로드한다.
3. 서비스가 열 이름과 데이터 형식을 인식하고 표준 필드에 매핑한다.
4. 불확실한 모델명·부품번호·수리 결과는 수리점 담당자가 확인한다.
5. 고객 식별정보와 개별 장비 일련번호 등 불필요한 필드를 제거한다.
6. 최소 표본 기준을 충족하는 집계 결과만 대시보드에 반영한다.
7. 수리점은 무료로 자신의 기록 품질과 지역·제품군별 익명 벤치마크를 확인한다.
8. 제조사·부품 유통사는 별도 계약과 권한에 따라 집계된 수리·부품 수요 신호를 확인한다.

## 6. 목표 고객과 사용해야 하는 이유

### 데이터 제공자

- 소형 가전·생활가전 독립 수리점
- 커피머신·진공청소기 등 특정 제품군 전문 수리점
- 중고 가전 리퍼비셔 및 재제조 사업자
- 여러 지점을 운영하는 독립 수리 네트워크

### 유료 고객

- 가전 부품 수입·유통사
- 제조사 서비스·품질·제품기획 조직
- 보증·수리 네트워크 운영사
- 리퍼비시·재제조 사업자

### 고객이 사용할 이유

**수리점**
- 기존 작업 기록을 새로 입력하지 않고 업로드만으로 참여할 수 있다.
- 자사 제품군의 반복 고장·부품 조달 추세를 확인할 수 있다.
- 익명 벤치마크를 통해 재고와 수리 업무의 우선순위를 검토할 수 있다.

**부품 유통사**
- 실제 수리 현장에서 반복적으로 찾는 부품과 미충족 수요를 파악할 수 있다.
- 특정 지역·제품군에서 부품 수요가 늘어나는지 확인할 수 있다.
- 재고·구매 계획을 경험만이 아니라 집계된 수요 신호로 검토할 수 있다.

**제조사**
- 공식 서비스망 밖의 수리 현장에서 나타나는 문제를 추가로 파악할 수 있다.
- 부품 공급·수리성 개선이 필요한 모델을 찾는 보조 자료로 활용할 수 있다.

위 가치는 모두 가설이다. 데이터 제공자가 충분히 모이지 않거나 구매자가 집계 데이터에 비용을 지불하지 않으면 사업성이 성립하지 않는다.

## 7. 수익 모델 가설

아래 가격은 시장에서 검증된 가격이 아니라 초기 인터뷰용 가설이다.

| 플랜 | 가격 가설 | 제공 범위 |
|---|---:|---|
| Repair Shop Contributor | 무료 | 데이터 업로드, 본인 기록 품질 확인, 기본 익명 벤치마크 |
| Distributor | 월 ₩199,000~₩499,000 | 제품군·지역별 부품 부족 신호, 추세 대시보드, 월간 리포트 |
| Manufacturer | 월 ₩1,000,000~₩3,000,000 | 다수 제품군 분석, 모델별 집계, 분기별 보고서, API 협의 |
| Custom Insight Report | 건당 ₩1,000,000~₩3,000,000 | 특정 제품군·지역·기간의 맞춤 분석 |

초기에는 구독 판매보다 1회성 유료 분석 보고서로 지불 의사를 검증한다. 유료 고객이 확보되고 데이터가 반복적으로 갱신될 때 구독형으로 전환한다.

**중요:** 원본 수리 티켓이나 개인 식별정보를 판매하는 모델은 사용하지 않는다. 데이터 제공자의 명시적 동의 범위 안에서 비식별·집계 결과만 제공한다.

## 8. MVP 개발 범위

### 첫 번째 파일럿 범위

- 제품군: 진공청소기·커피머신 등 소형 가전 중 한 분야부터 시작
- 데이터 제공자: 독립 수리점 5~10곳
- 목표 데이터: 비식별 수리 기록 300~500건
- 구매자 후보: 부품 유통사 2곳 이상

### 반드시 구현할 기능

1. CSV·XLSX 업로드
2. 열 이름 자동 인식과 수동 매핑
3. 브랜드·모델·고장 유형·부품 상태·수리 결과 표준화
4. 불완전하거나 중복된 레코드 표시
5. 부품 미확보·조달 지연·수리 미완료 통계
6. 표본 수와 데이터 최신성을 함께 보여주는 대시보드
7. PDF·CSV 리포트 내보내기
8. 데이터 제공 동의·철회 및 삭제 요청 처리

### 초기 버전에서 제외할 기능

- 수리점 POS 전체 대체
- 모든 POS·ERP의 실시간 API 연동
- 자동 부품 호환성 판정
- AI의 고장 원인 확정 또는 수리 방법 추천
- 고객 개인별 수리 기록 검색
- 검증되지 않은 시장 수요 예측

## 9. 기술 구현 제안

- Frontend: Next.js + TypeScript
- Backend: Cloudflare Workers 또는 Supabase
- Database: PostgreSQL
- File storage: Cloudflare R2
- Import: CSV·XLSX 파서 + 사용자 확인형 필드 매핑
- Analytics: SQL 집계 및 통계 규칙
- Optional AI: 고장 메모 분류 후보 추출
- Auth: Supabase Auth
- Reports: 서버 측 PDF 및 CSV 내보내기

### 데이터 신뢰성·개인정보 원칙

- 고객 이름, 전화번호, 주소, 이메일, 장비 일련번호는 초기 수집 대상에서 제외한다.
- 매장 식별정보와 원본 파일은 집계 데이터와 분리해 저장한다.
- 계약과 동의 없이 원본 데이터나 매장별 영업 정보를 제조사·유통사에 제공하지 않는다.
- 특정 매장이나 소수 고객이 추정될 수 있는 작은 집계 그룹은 표시하지 않는다.
- 모든 지표에 표본 수, 집계 기간, 누락률, 갱신 시각을 표시한다.
- AI가 분류한 값은 확정 사실이 아니라 검토가 필요한 후보로 저장한다.
- 데이터 제공자가 철회·삭제를 요청할 수 있는 절차를 둔다.

## 10. 고객 확보 전략

### 데이터 제공자 확보

1. 소형 가전·커피머신·진공청소기 전문 수리점 20곳에 직접 인터뷰 요청
2. 기존 작업 이력의 CSV 내보내기 가능 여부와 개인정보 포함 여부 확인
3. 실제 고객정보가 제거된 샘플 파일로 가져오기 데모 제공
4. 초기 참여 수리점에 무료 기록 품질 리포트와 익명 벤치마크 제공
5. 지역 수리점 협회·부품 도매상·리퍼비셔 네트워크와 제휴 검토

### 유료 고객 확보

1. 부품 유통사 구매·상품기획 담당자에게 샘플 집계 보고서 제공
2. '어떤 부품이 부족한가'보다 '어떤 제품군에서 미완료 수리가 반복되는가'를 먼저 보여준다.
3. 특정 제품군과 지역에 한정한 유료 분석 파일럿 제안
4. 구매자가 실제 재고·소싱 결정에 활용했는지 후속 인터뷰
5. 데이터가 충분해진 뒤 제조사 품질·서비스 조직으로 확장

초기에는 광고보다 직접 인터뷰와 데이터 샘플 검증이 우선이다. 양측 네트워크를 동시에 확보해야 하는 콜드스타트 위험이 크다.

## 11. 초기 비용 및 운영 리스크

### 비용 가설

- MVP 개발: CSV 업로드·정규화·집계 중심으로 범위를 제한하면 현금 비용을 낮출 수 있다.
- 인프라: 초기에는 무료·저가 클라우드 구간으로 시작하되, 파일 저장·백업·쿼리 비용을 측정한다.
- AI: 핵심 집계에 사용하지 않고 필요할 때만 분류 후보 추출에 사용한다.
- 주요 비용: 데이터 정제, 고객별 파일 매핑, 보안·백업, 고객 인터뷰, 수리점 온보딩.
- 초기에는 데이터 매핑과 영업 지원에 드는 인건비가 인프라 비용보다 클 가능성이 있다.

### 리스크와 대응

- **콜드스타트:** 수리점 데이터가 충분하지 않으면 구매자에게 의미 있는 분석을 제공할 수 없다. 한 제품군·한 지역부터 시작한다.
- **데이터 품질:** 모델명 오기, 부품번호 누락, 수리 결과 편향이 발생할 수 있다. 원본 행과 정규화 결과를 연결하고 불확실성을 표시한다.
- **표본 편향:** 특정 브랜드·지역·수리점이 과대표집될 수 있다. 표본 수와 참여자 구성을 공개하고 전체 시장으로 일반화하지 않는다.
- **개인정보·영업비밀:** 원본 파일에 고객정보와 거래 조건이 포함될 수 있다. 최소 수집, 비식별화, 접근 통제, 명시적 동의, 삭제 정책이 필요하다.
- **데이터 소유권:** 데이터 제공 계약에서 사용 목적, 보유 기간, 집계·재사용 권한, 철회 절차를 명확히 한다.
- **경쟁사 기능 확장:** 기존 수리 POS나 부품 플랫폼이 유사한 분석 기능을 추가할 수 있다. 여러 업체를 가로지르는 독립 데이터와 표준화 품질을 차별화 자산으로 만든다.
- **구매자 부재:** 제조사·유통사가 분석 데이터를 구매하지 않을 수 있다. 제품 개발 전에 샘플 보고서로 구매 의향을 확인한다.
- **잘못된 판단 유발:** 데이터는 수요 신호이지 부품 호환성·제품 안전성·수리 가능성의 보증이 아니다. 기술적 판단을 자동화하지 않는다.

## 12. 30일 시장 검증 계획

### 1~7일: 데이터 접근 가능성 확인

- 독립 수리점 15곳 인터뷰
- 작업 이력의 저장 형식과 CSV 내보내기 가능 여부 확인
- 부품 부족·조달 지연·수리 포기 기록이 실제로 존재하는지 조사
- 데이터 제공 동의에 대한 우려와 허용 범위 확인

### 8~14일: 수동 데이터 파일럿

- 동의받은 비식별 샘플 300건 이상 확보 목표
- 브랜드·모델·고장·부품 상태·수리 결과를 수작업으로 표준화
- 표준화 성공률과 필드 누락률 측정
- 기존 수리점 시스템에서 쉽게 추출할 수 있는 항목과 없는 항목 분리

### 15~22일: 구매자 검증

- 부품 유통사·제조사 담당자 5명 인터뷰
- 실제 집계 보고서 샘플 제공
- 어떤 결정에 활용할 수 있는지, 현재 어떤 데이터를 쓰는지 질문
- 무료 데모가 아닌 유료 파일럿 제안에 대한 반응 확인

### 23~30일: 최소 제품 및 유료 검증

- CSV 업로드·정규화·부품 부족 집계 대시보드 구현
- 최소 5개 수리점의 데이터로 첫 제품군 보고서 생성
- 유통사 1곳 이상에 유료 파일럿 제안
- 데이터 품질과 구매 의사가 모두 확인될 때만 다음 개발 단계로 이동

### 진행 기준 가설

- 수리점 15곳 중 5곳 이상이 비식별 데이터 제공에 동의
- 업로드한 기록 중 브랜드·모델·수리 결과 필드가 70% 이상 채워짐
- 부품 미확보 또는 조달 지연 사례를 구조화할 수 있는 기록이 실제로 존재
- 유통사·제조사 담당자 5명 중 2명 이상이 샘플 보고서 후속 검토에 동의
- 최소 1곳이 유료 분석 파일럿을 검토하거나 구매 의향서를 제공

위 수치는 검증을 위한 내부 목표이며 시장 평균이나 확정된 성과 기준이 아니다. 충족하지 못하면 구독형 제품 개발을 보류하고 데이터 제공자 또는 구매자 중 어느 쪽에서 가치가 부족한지 재검토한다.

## 13. 핵심 성과 지표

- 월간 데이터 제공 수리점 수
- 월간 신규 수리 기록 수
- 필수 필드 완성률과 표준화 성공률
- 부품 미확보·조달 지연 데이터의 비율
- 데이터 갱신 주기와 제공자 재참여율
- 구매자 샘플 보고서 열람 후 후속 미팅 전환율
- 유료 파일럿 수와 반복 구매율
- 수리점 온보딩 및 데이터 정제에 걸리는 시간
- 데이터 삭제·철회 요청 처리 시간

## 14. 사업성 평가

| 평가 항목 | 현재 판단 |
|---|---|
| 문제의 실재 가능성 | 중간 — 수리 데이터 분산과 부품 조달 문제는 합리적 가설이나 상업 수리점 인터뷰 전 |
| 데이터 확보 가능성 | 미검증 — 기존 POS에서 필요한 항목을 얼마나 추출할 수 있는지 확인 필요 |
| 지불 의사 | 미검증 — 제조사·유통사 유료 파일럿 필요 |
| 경쟁 강도 | 중간~높음 — 수리점 POS, 커뮤니티 수리 데이터, 자동차 수리 분석 제품 존재 |
| 기술적 MVP 난이도 | 중간 — CSV 정규화보다 데이터 품질·동의·표본 확보가 핵심 난제 |
| 초기 현금 비용 | 낮음~중간 — 파일럿은 수작업으로 시작 가능하나 데이터 온보딩 비용 존재 |
| 고객 획득 난이도 | 높음 — 데이터 제공자와 구매자를 모두 확보해야 함 |
| 확장성 | 중간~높음 — 소형 가전에서 다른 소비자 제품군과 지역으로 확장 가능성 |
| 차별성 | 미검증 — 독립 수리점의 상세 부품 조달 데이터를 유료 구매자가 원하는지 확인 필요 |
| 현재 결정 | 데이터 파일럿과 유료 분석 보고서부터 검증 |

**결론:** RepairSignal은 수리점 운영 소프트웨어를 하나 더 만드는 아이디어가 아니다. 독립 수리점에 흩어진 부품 부족·조달 기간·수리 결과 데이터를 표준화해 제조사와 부품 유통사의 의사결정에 활용하는 데이터 사업이다. 핵심 자산은 AI 기능이 아니라 데이터 제공자의 동의, 표준화 품질, 충분한 표본, 구매자가 실제로 사용하는 분석 결과다. 데이터 제공자 5곳과 유료 분석 구매자 1곳을 확보하지 못하면 본격 개발을 보류한다.
