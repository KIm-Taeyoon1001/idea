# IDEA-007 — RefracSpec

> **한 줄 설명:** 여러 내화물 공급사의 기술자료(TDS)와 배치별 시험성적서(COA)를 고객 프로젝트의 요구조건에 맞춰 출처·시험방법·측정조건까지 보존하며 비교하고, 기술 검토 및 RFQ에 필요한 증빙 패키지를 만드는 B2B SaaS.

- **작성일:** 2026-11-13
- **상태:** 초기 사업 가설 — 고객 인터뷰 및 유료 파일럿 전
- **제품명:** RefracSpec은 작업명이며 상표·도메인 사용 가능 여부는 확인하지 않았다.
- **핵심 경계:** 제품은 기술자료의 정리·비교·누락 확인을 지원한다. 내화물의 설계, 최종 재료 선정, 대체재 승인, 성능 보증 또는 안전 인증을 수행하지 않는다.

## 1. 발견한 불편함

내화물 구매·보수 프로젝트에서는 제조사와 공급사마다 제품명, 등급 표기, 기술자료 양식, 단위, 시험방법, 시험 온도와 자료의 상세 수준이 다를 수 있다. 기술 담당자는 여러 PDF 카탈로그와 TDS를 열어 화학 조성, 벌크 밀도, 겉보기 기공률, 상온 압축강도, 하중 연화 특성, 열전도율, 사용 온도, 치수 등의 항목을 직접 옮겨 비교해야 한다.

이때 단순히 숫자만 나란히 놓으면 잘못된 비교가 될 수 있다.

- 같은 물성명이라도 시험 규격·시험편 상태·시험 온도·측정 조건이 다를 수 있다.
- 제조사의 TDS에 기재된 대표값과 특정 생산 배치의 COA 결과는 의미가 다르다.
- 자료에 값이 없거나 범위로만 표시된 항목을 담당자가 이메일로 다시 확인해야 한다.
- 오래된 TDS와 최신 제품 개정판이 혼재하면 어떤 자료를 근거로 검토했는지 추적하기 어렵다.
- 프로젝트별 요구조건과 공급사 자료를 연결하지 못하면 검토자가 같은 비교 작업을 반복할 수 있다.

**검증할 문제 가설:** 내화물 시공업체, 플랜트 유지보수팀, 전문 유통사가 여러 공급사의 기술자료를 비교하고 누락 항목을 확인하는 데 반복적으로 많은 시간을 쓰며, 이 업무를 줄이는 도구에 비용을 지불할 의사가 있는가?

현재 이 문제가 모든 업체에서 빈번하다는 사실이나 시장 규모는 확인되지 않았다. 실제 프로젝트의 자료와 비교 소요 시간을 확보해야 한다.

## 2. 문제의 근본 원인

1. **제품 식별 체계의 차이:** 제조사별 제품명·등급·규격이 달라 이름 검색만으로 동등 제품을 찾기 어렵다.
2. **자료의 비정형성:** 핵심 데이터가 PDF 표, 스캔 문서, 카탈로그, 이메일 첨부 파일에 분산될 수 있다.
3. **시험 조건의 차이:** 물성값은 시험방법과 조건을 함께 봐야 한다. 숫자와 단위만 정규화하면 의미가 왜곡될 수 있다.
4. **자료 유형의 혼재:** TDS의 대표·보증 범위와 특정 로트의 COA 실측값이 한 표에 섞일 수 있다.
5. **근거 추적의 어려움:** 비교표의 값이 어느 문서의 몇 페이지, 어느 개정판에서 추출됐는지 남지 않으면 검토와 감사가 어렵다.
6. **검토 기준의 프로젝트 종속성:** 같은 제품이라도 적용 구역, 운전 조건, 고객 시방서에 따라 필요한 검토 항목이 달라질 수 있다.

위 원인은 고객 인터뷰 전의 설계 가설이다. 실제 업무 흐름에서 어떤 원인이 가장 큰지 확인해야 한다.

### 표준과 시험방법 관련 근거

- [ASTM C201-24](https://store.astm.org/c0201-24.html)는 내화물 열전도율 시험방법을 다루며, 시험 결과의 평균 온도와 정상상태 등 조건이 중요하다고 설명한다.
- [ASTM C133-24](https://store.astm.org/c0133-24.html)는 내화물의 상온 압축강도 및 파괴계수 시험방법을 다루고, 상온 강도가 고온에서의 성능을 직접 측정하는 값은 아니라고 명시한다.
- [ASTM C20](https://store.astm.org/standards/c20)는 소성 내화 벽돌·형상의 겉보기 기공률, 흡수율, 겉보기 비중, 벌크 밀도 시험방법을 다룬다.

이 자료들은 **시험방법과 조건을 무시한 숫자 비교가 위험할 수 있음**을 보여준다. RefracSpec은 표준 전문을 복제하거나 표준의 적합성을 판정하지 않는다. 고객이 보유한 규격명·판본과 공급사 자료의 시험방법 표기를 기록하고, 불명확한 항목은 비교 불가 또는 확인 필요로 표시한다.

### 경쟁 조사 결론

내화물 비교표, 열해석 도구, 범용 재료 선택 소프트웨어, 산업재 RFQ, 잔여 재고 마켓플레이스가 이미 존재한다. 따라서 '내화물 검색 서비스'나 'AI 재료 추천'을 새로운 시장이라고 주장하지 않는다.

**차별화 가설:** 여러 공급사의 원본 TDS·COA를 프로젝트 요구조건에 연결하고, 각 비교값의 출처 페이지·개정판·시험방법·온도·단위·자료 유형을 보존하며, 서로 비교할 수 없는 값은 억지로 점수화하지 않는 검토 워크플로에는 별도 수요가 있을 수 있다.

## 4. 차별화 설계

1. **출처가 붙은 값:** 추출된 모든 값에 원본 파일, 페이지, 표/행, 문서 개정일을 연결한다.
2. **시험방법을 보존:** ASTM/ISO/EN 등 규격 식별자와 판본, 시험 온도, 시험편 상태, 측정 조건을 별도 필드로 저장한다.
3. **자료 유형 분리:** TDS 대표값, 제조사 보증 범위, COA의 로트별 실측값을 구분한다.
4. **비교 가능성 상태:** 요구조건 내 문서화, 요구조건 밖, 자료 없음, 시험조건 불일치, 공급사 확인 필요로 표시한다.
5. **무근거 점수 금지:** 임의의 AI 적합도 점수나 '동등품 인증' 배지를 만들지 않는다. 고객이 정의한 수치 범위와 확인 규칙만 적용한다.
6. **검토 책임 분리:** 기술 담당자가 각 항목을 확인·수정하고 승인자와 검토 시점을 기록한다.
7. **질문 자동 정리:** 빠진 시험방법, 최신 COA, 적용 온도에서의 열전도율 등 공급사에 확인할 질문을 문서화한다.

## 5. 제품 설명 및 사용 흐름

### 기본 사용 흐름

1. 사용자가 프로젝트와 검토 대상 구역을 만든다.
2. 고객 시방서 또는 내부 요구조건을 항목별로 입력한다.
3. 여러 공급사의 TDS와 해당 배치 COA를 업로드한다.
4. 문서 파서가 표와 수치를 추출하고, 각 값에 원본 페이지와 문서 정보를 연결한다.
5. 사용자가 추출값과 시험 조건을 검토·확정한다.
6. 시스템은 입력된 요구조건과 확인된 자료를 비교해 누락·범위 이탈·비교 불가 항목을 구분한다.
7. 공급사 확인 질문과 RFQ 첨부용 비교 보고서를 생성한다.
8. 지정된 기술 검토자가 결과를 확인하고 승인 여부를 별도로 기록한다.

### 핵심 화면

- 프로젝트 요구조건
- 공급사·제품 카탈로그
- 원본 문서와 추출 데이터의 나란히 보기
- 시험방법·조건 비교표
- 자료 누락 및 확인 질문 목록
- 검토자·승인 이력
- PDF/CSV 보고서 내보내기

### 제품이 하지 않는 일

- 사용 조건만으로 특정 내화물을 자동 추천하지 않는다.
- 서로 다른 시험방법의 값을 단순 환산해 동등하다고 판정하지 않는다.
- 제품의 실제 성능, 수명, 안전성 또는 인증을 보증하지 않는다.
- 고객 시방서나 유료 표준 전문을 무단 수집·복제하지 않는다.
- 공급사에 자동 발주하거나 대체재를 자동 승인하지 않는다.

## 6. 타깃 고객

**초기 고객 가설**

1. 여러 제조사 제품을 검토하는 내화물 시공·보수 전문업체의 기술·견적 담당자
2. 공장 정기보수와 설비 개조 때 대체 제품을 검토하는 플랜트 유지보수·구매팀
3. 여러 제조사의 제품을 취급하고 고객별 기술자료를 반복 제출하는 전문 내화물 유통사

**초기 진입 범위:** 한 국가·한 제품군·소수 공급사로 제한한다. 첫 제품군은 기술자료 항목을 비교적 구조화하기 쉬운 **단열 내화 벽돌**로 가정한다. 이 선택은 고객 인터뷰에서 실제 문서량과 구매 빈도를 확인한 뒤 변경할 수 있다.

## 7. 사람들이 사용해야 할 이유

- 여러 PDF의 표를 수작업으로 옮기고 다시 검토하는 시간을 줄일 수 있다.
- 숫자만 같아 보이는 서로 다른 시험 조건을 초기에 발견할 수 있다.
- 자료가 없는 항목과 공급사에 물어봐야 할 질문을 명확히 할 수 있다.
- 비교표의 근거를 원본 페이지까지 역추적할 수 있다.
- 담당자가 바뀌어도 프로젝트별 기술 검토 이력을 이어갈 수 있다.

이 가치는 아직 가설이다. 고객이 기존 엑셀·문서 양식으로 충분히 빠르고 정확하게 일하고 있다면 별도 제품을 구매할 이유가 없을 수 있다.

가격은 실제 구매 의사와 문서 처리량을 확인하기 전의 가설이다. 특히 프로젝트당 결제와 월 구독 중 어느 방식이 더 적합한지 인터뷰로 비교한다.

## 9. MVP 범위

**목표:** 3~4주 안에 실제 TDS 비교 업무 한 건을 보조할 수 있는 최소 제품을 만든다.

포함 기능:

1. 이메일 로그인과 프로젝트 생성
2. PDF 업로드 및 원본 보관
3. 첫 제품군의 핵심 필드 10~15개 추출
4. 값마다 페이지·문서명·개정일·시험방법·단위 연결
5. 추출값의 사람 검토 및 수정
6. 프로젝트 요구조건과의 범위 비교
7. 자료 없음·시험조건 불일치·공급사 확인 필요 표시
8. 비교표 PDF/CSV 내보내기
9. 검토자와 승인 시점 기록

초기에는 공개 TDS 또는 고객이 사용 권한을 보유한 자료 20~30개로 수작업 검증한다. OCR/AI 추출은 초안 작성에만 사용하고, 기술값은 사람이 확인하기 전 확정 데이터로 취급하지 않는다.

제외 기능:

- 전체 내화물 시장 검색 엔진
- 공급사 마켓플레이스와 결제
- 열전달·라이닝 두께 설계 계산
- 자동 대체재 추천
- ERP·MES·PLM 대규모 통합
- 유료 표준 전문의 저장·배포

## 10. 고객 확보 전략

1. 내화물 시공업체·유통사·플랜트 기술 담당자 10명을 대상으로 비교 업무를 인터뷰한다.
2. 고객이 공개적으로 배포했거나 사용 허가를 받은 TDS를 받아 실제 비교표를 수작업으로 만든다.
3. 기존 엑셀 방식과 RefracSpec 시제품의 작업 시간을 비교한다.
4. 무료 데모 대신 실제 프로젝트 1건에 적용하는 제한된 파일럿을 제안한다.
5. 첫 고객의 동의를 받아 익명화된 샘플 비교 보고서를 기술 콘텐츠로 공개한다.
6. 공급사 영업 담당자와 협력하되 특정 제조사 제품을 우선 노출하는 광고 모델은 초기에는 배제한다.

## 11. 초기 비용 및 기술 운영 가설

### 개발 구성

- Frontend: TypeScript + Next.js
- Backend/API: Cloudflare Workers 또는 Next.js API
- Database/Auth: Supabase PostgreSQL/Auth
- File storage: S3 호환 객체 저장소
- PDF extraction: 텍스트 추출 우선, 스캔 문서에만 OCR 적용
- Document parsing: 표 추출 + 규칙 기반 필드 매핑 + 선택적 LLM 보조
- Export: 서버 측 PDF 및 CSV 생성

### 비용 가설

- 개발 초기: 기존 무료 개발 도구와 무료 사용량을 활용해 현금 지출을 최소화한다.
- 소규모 파일럿: 저장 용량과 OCR 호출량에 따라 월 0~50,000원 수준을 목표로 하되, 실제 제공자 요금과 사용량을 확인해야 한다.
- LLM 사용은 필수 단계가 아니다. 가능한 값은 로컬 파서와 규칙으로 추출하고, 모호한 문서에만 선택적으로 사용한다.
- 가장 큰 초기 비용은 서버비보다 내화물 분야의 데이터 구조 정의, 문서 검수, 전문가 인터뷰 시간일 가능성이 있다.

위 금액은 공급사 견적을 받은 확정 비용이 아니라 MVP 예산을 잡기 위한 추정치다.

## 12. 확장성

첫 제품군에서 반복 사용과 지불 의사가 확인되면 다음으로 확장할 수 있다.

1. 캐스터블, 세라믹 파이버, 단열재 등 인접 내화물 제품군
2. 공급사 포털을 통한 최신 TDS·COA 제출 및 개정 알림
3. 프로젝트별 고객 시방서 템플릿과 검토 규칙
4. 기술자료 데이터의 API 내보내기와 구매·품질 시스템 연동
5. 공급사 응답과 검토 완료 이력을 연결한 RFQ 협업

확장은 고객이 실제로 요청한 순서로만 진행한다. 데이터베이스 규모를 먼저 늘리거나 마켓플레이스를 선행하지 않는다.

## 13. 법적·운영상 리스크

| 리스크 | 대응 |
|---|---|
| 잘못 추출된 물성값 | 원본 페이지·표 위치를 보존하고 사람의 확인 전에는 미확정으로 표시한다. |
| 시험방법·조건이 다른 값의 오비교 | 시험방법·판본·온도·시험편 조건을 별도 저장하고 비교 불가 상태를 제공한다. |
| TDS 대표값과 COA 로트값 혼동 | 문서 유형과 대상 로트·발행일을 구분한다. |
| 잘못된 대체재 판단으로 인한 손실 | 자동 추천·승인·성능 보증을 하지 않는다. 최종 기술 판단은 고객의 자격 있는 담당자가 수행한다. |
| 표준 문서 저작권 | 표준 전문이나 표준 표를 복제하지 않는다. 고객이 보유한 규격 식별자와 판본 등 필요한 메타데이터만 기록한다. |
| 공급사 자료의 영업비밀 | 테넌트 분리, 접근권한, 전송·저장 암호화, 보존기간 설정, 삭제·내보내기 기능을 제공한다. |
| 오래된 문서 사용 | 문서 개정일과 업로드일을 구분하고 최신본 확인 필요 상태를 표시한다. |
| 긴 B2B 영업 주기 | 처음에는 문서 1건 단위 파일럿으로 진입하고 반복 구매 빈도를 검증한다. |
| 공급사 편향 | 유료 노출 순위나 후원 제품 점수를 초기 제품에 넣지 않는다. |

## 14. 30일 시장 검증 계획

### 1주 차 — 문제 확인
- 시공업체·유통사·플랜트 기술 담당자 10명 인터뷰
- 최근 3개월 내 공급사 제품 비교 사례, 참여자, 사용 문서, 소요 시간 파악
- 기존 엑셀·카탈로그·내부 DB로 문제가 해결되는지 확인

### 2주 차 — 실제 자료 검증
- 사용 허가를 받은 TDS 20~30개 확보
- 단열 내화 벽돌의 핵심 비교 필드 10~15개 정의
- 문서 추출 결과를 전문가가 직접 작성한 기준표와 대조
- 시험방법·조건 누락과 비교 불가 사례를 분류

### 3주 차 — 시제품 파일럿
- 사용자 3명에게 프로젝트별 비교표 생성 기능 제공
- 원본 페이지 근거를 찾는 시간과 누락 질문 수 측정
- 추출 오류를 사용자가 수정할 수 있는지 확인

### 4주 차 — 지불 의사 검증
- 실제 프로젝트 1건에 유료 파일럿 제안
- 프로젝트당 결제와 월 구독 중 선호 방식 확인
- 구매 승인권자, 보안 요구, 문서 공유 제한 확인

### 핵심 검증 지표와 잠정 통과 기준

- 인터뷰 10명 중 5명 이상이 최근 3개월 내 여러 공급사 기술자료를 반복 비교했다고 확인
- 실제 문서 20개 이상에서 주요 필드 추출·검수 가능성 확인
- 파일럿 사용자 3명 중 2명 이상이 기존 방식보다 검토 시간이 줄었다고 평가
- 1개 이상의 유료 파일럿 또는 구체적인 구매 승인 절차 확인

위 숫자는 초기 의사결정 기준이지 이미 달성한 성과가 아니다.

**중단 기준:** 인터뷰 대상 대부분이 공급사 비교를 거의 하지 않거나, 기존 시스템으로 충분히 해결하고 있거나, 외부 서비스에 기술자료를 업로드할 수 없거나, 비용을 지불할 담당자가 확인되지 않으면 제품 범위를 재검토한다.

## 15. 기존 저장소 아이디어와의 중복 검토

- **IDEA-003 LiningProof:** 내화물 시공 현장의 자재 Lot·검사·건조·품질 증빙을 기록한다. RefracSpec은 구매 전 단계에서 여러 공급사의 기술자료를 비교하고 검토 근거를 관리한다. 구매자·업무 시점·핵심 데이터가 다르다.
- **IDEA-005 MachHandoff:** 중고 CNC 장비 거래의 제어기·백업·라이선스 인계를 다룬다. RefracSpec은 산업용 내화물 제품의 기술자료 비교를 다룬다.
- **IDEA-002 DeductLens:** 납품 정산 차감의 반복 원인을 분석한다. RefracSpec은 물성·시험조건의 문서 비교를 다룬다.
- **IDEA-001 ChangeLedger:** 공개 웹페이지의 변경을 추적한다. RefracSpec은 사용 권한이 있는 기술문서를 구조화하고 프로젝트 요구조건과 대조한다.

동일 산업군인 IDEA-003과 연관성은 있지만, 같은 제품의 이름 변경이나 기능 복제는 아니다. 다만 실제 고객 인터뷰에서 구매 담당자와 현장 품질 담당자의 업무가 하나의 기존 시스템으로 충분히 처리된다고 확인되면 별도 제품의 필요성이 낮아질 수 있다.
