# IDEA-009 — AwardRelay

> **한 줄 설명:** 연방·공공 보조금으로 구매한 장비를 여러 부서와 협력 기관이 공동으로 사용하는 조직을 위해, 대여 승인·인수인계·실제 사용 목적·반납 상태와 보조금 관련 증빙을 한 흐름으로 연결하는 공유 장비 운영 SaaS.

- **조사 기준일:** 2026-11-15
- **상태:** 초기 사업 가설 — 고객 인터뷰 및 유료 파일럿 전
- **초기 시장 가설:** 미국의 지방정부·지역 비영리 컨소시엄·공공 프로그램 운영기관 중 보조금으로 구매한 장비를 여러 부서 또는 협력 기관에 공유하는 조직
- **제품 범위:** 공유 장비 요청, 승인, 인수인계, 실제 사용 기록, 반납 확인, 증빙 내보내기
- **중요한 경계:** 보조금 규정의 법적 해석이나 적격성 판단을 자동으로 확정하지 않는다. 조직의 보조금 담당자가 승인한 조건을 기록하고, 사용자가 증빙을 남기도록 돕는다.

---

## 1. 발견한 불편함

지방정부, 비영리기관, 지역 컨소시엄은 보조금으로 구매한 노트북, 카메라, 이동형 장비, 통신·행사 장비, 교육 장비 등을 한 부서만 사용하지 않고 여러 부서나 협력 기관에 빌려줄 수 있다.

이때 단순 자산 목록만으로는 실제 공유 운영을 설명하기 어렵다.

- 어떤 재원과 보조금으로 구매했는가?
- 누가 장비를 보유하고 있는가?
- 다른 부서나 협력 기관에 빌려줄 수 있는가?
- 대여를 누가 승인했으며, 어떤 프로그램 목적으로 사용했는가?
- 장비가 언제 인계되고 반납되었는가?
- 반납 당시 상태와 누락된 구성품은 무엇인가?
- 감사나 내부 검토 때 해당 사용 이력을 어떤 자료로 설명할 수 있는가?

이 정보가 자산관리 시스템, 대여대장, 보조금 파일, 이메일, 종이 인수증, 사진에 나뉘어 있으면 담당자가 장비 한 건의 전체 이력을 재구성해야 할 수 있다.

**핵심 문제 가설:** 보조금으로 취득한 공유 장비의 소유·위치 정보는 관리하더라도, 여러 부서·협력 기관 사이의 요청부터 실제 사용 목적과 반납 증빙까지 한 흐름으로 연결하지 못하는 조직이 존재한다.

이는 아직 검증되지 않은 가설이다. 조직마다 자산관리·대여·보조금 시스템이 다르고, 이미 충분히 통합된 곳도 있을 수 있다.

## 2. 문제의 근본 원인

1. **시스템 분리:** 자산관리 시스템은 자산의 소유·위치·상태를, 보조금 관리 시스템은 예산·보고·증빙을, 대여 도구는 예약 일정을 각각 다룬다.
2. **기관 간 인수인계:** 장비가 부서 밖이나 협력 기관으로 이동하면 일반적인 사내 자산 대여보다 책임자·승인·반납 확인이 복잡해진다.
3. **사용 목적의 맥락 부족:** 단순히 누가 장비를 빌렸는지만으로는 어느 프로그램에서 어떤 목적으로 사용했는지 설명하기 어렵다.
4. **보조금 조건의 차이:** 장비마다 재원, 수여기관, 승인 조건과 사용 목적이 다를 수 있다. 모든 장비에 같은 규칙을 적용할 수 없다.
5. **증빙 재구성 비용:** 감사나 보조금 보고 시점에 과거 이메일·사진·서명·대여대장을 다시 모아야 할 수 있다.

## 3. 규제·시장 신호

### 미국 연방 보조금 장비 관리 규정

2026-11-12 기준 eCFR의 2 CFR § 200.313은 연방 보조금으로 취득한 장비에 대해 사용·관리·처분 조건을 규정한다.

- 장비는 승인된 프로젝트 목적에 사용해야 한다.
- 원래 목적을 방해하지 않는 범위에서 다른 연방 지원 프로그램에도 장비를 사용할 수 있도록 해야 하며, 동일 연방기관의 다른 프로그램에 우선순위를 둔다.
- 자산 기록에는 재원(FAIN 포함), 취득일·비용, 위치, 사용, 상태와 처분 정보 등이 포함되어야 한다.
- 자산의 물리적 실사는 최소 2년에 한 번 수행하고 자산 기록과 대조해야 한다.
- 손실·손상·도난에 대한 통제와 정기 유지관리 절차도 요구된다.

공식 원문: [eCFR — 2 CFR § 200.313 Equipment](https://www.ecfr.gov/current/title-2/section-200.313)

**적용 범위 주의:** 이 규정이 모든 공공·비영리 장비에 동일하게 적용되는 것은 아니다. 조항은 연방 보조금 수령자·하위 수령자에 관한 것이며, 주정부와 부족 정부에는 별도 법령·절차가 적용될 수 있다. 실제 조건은 개별 보조금 계약과 수여기관 지침을 확인해야 한다. AwardRelay는 법률 자문이나 규정 준수 보증을 제공하지 않는다.

### 경쟁 조사 결론

이 아이디어는 자산관리, 보조금 장비 기록, 공유 장비 예약이라는 세 영역이 만나는 곳에 있다. 이미 보조금 자산관리 제품과 공유 장비 운영 제품이 존재하므로, 새로운 자산관리 시스템이나 범용 예약 도구를 만들면 차별성이 약하다.

AwardRelay의 차별화 가설은 다음과 같이 좁힌다.

- 기존 자산관리 시스템을 대체하지 않고 CSV/API로 자산 기본정보를 가져온다.
- 한 조직 안의 대여뿐 아니라 여러 부서·협력 기관 사이의 요청과 인수인계를 기록한다.
- 장비의 재원·보조금·조직이 설정한 사용 조건을 대여 승인 과정에 연결한다.
- 예약 시간만 저장하지 않고 실제 인수·사용 목적·반납 상태·구성품 확인을 남긴다.
- 기관별 권한을 분리하고, 한 건의 대여 이력을 승인·인수·반납 증빙과 함께 내보낸다.

공개된 기능 설명만으로 InventoryGrant, Wasp 또는 다른 경쟁 제품이 이 전체 흐름을 전혀 제공하지 않는다고 단정할 수는 없다. 데모와 고객 인터뷰에서 기존 제품의 실제 범위를 확인해야 한다. 기존 제품이 이미 이 문제를 충분히 해결한다면 개발하지 않는다.

## 5. 제안 제품 — AwardRelay

AwardRelay는 보조금으로 취득한 공유 장비의 기관 간 대여·사용·반납을 추적하는 운영 레이어다.

### 핵심 데이터 구조

- **Asset:** 장비 식별자, 일련번호, 소유 조직, 현재 위치, 상태
- **Funding Source:** 재원, 보조금 식별자(예: FAIN), 수여기관, 관련 문서
- **Use Conditions:** 보조금 담당자가 입력·승인한 사용 조건, 허용 조직·프로그램, 승인 필요 여부
- **Loan Request:** 요청 기관, 목적, 요청 기간, 요청자, 승인자
- **Custody Event:** 인계 시각, 인계자·수령자, 위치, 사진, 서명 또는 확인
- **Use Record:** 실제 사용 기간, 프로그램·프로젝트 코드, 사용 목적, 사용 담당자
- **Return Check:** 반납 시각, 상태, 구성품, 손상·누락 기록, 후속 조치
- **Evidence Pack:** 요청·승인·인수·사용·반납 기록과 첨부 문서의 묶음

### 기본 사용 흐름

1. 자산 담당자가 기존 자산 목록을 CSV로 가져온다.
2. 보조금 담당자가 장비별 재원과 승인된 사용 조건을 등록한다.
3. 협력 기관이 공유 장비 대여를 요청한다.
4. 지정된 담당자가 요청 목적과 기간을 검토하고 승인 또는 반려한다.
5. 장비 인계 시 QR을 스캔해 인계자·수령자·시각·상태를 기록한다.
6. 사용 종료 후 실제 사용 기간과 프로그램 코드를 기록한다.
7. 반납 시 사진·구성품·상태를 확인한다.
8. 자산 담당자는 전체 이력을 CSV/PDF로 내보낸다.

## 6. 타깃 고객과 실제 지불 고객

### 초기 타깃 고객

- 여러 부서가 공용 장비를 운영하는 지방정부
- 재난·지역사회 지원·교육 프로그램 장비를 공유하는 지역 비영리 컨소시엄
- 공공 보조금으로 취득한 장비를 협력 기관에 대여하는 프로그램 운영기관
- 여러 기관이 공동 자산 풀을 운영하는 지역 네트워크

### 구매자와 사용자

- **구매 의사결정자:** 보조금 관리자, 재무·자산관리 책임자, 지역 프로그램 책임자
- **실제 사용자:** 자산 담당자, 부서 관리자, 협력 기관의 장비 수령자
- **협력 사용자:** 승인된 외부 기관 담당자

### 고객이 비용을 지불할 이유

- 기관 간 장비 대여의 책임 소재를 명확히 한다.
- 대여 승인부터 반납까지 한 건의 이력을 남긴다.
- 실제 사용 목적과 보조금 재원 정보를 연결한다.
- 보조금 보고나 내부 검토 때 이메일과 종이 기록을 다시 모으는 시간을 줄인다.
- 장비 공유 현황과 이용률을 확인해 불필요한 중복 구매를 줄일 가능성이 있다.

마지막 항목은 검증 전 가설이다. 장비 공유가 실제로 구매 예산을 줄이는지 고객별로 측정해야 한다.

## 8. MVP 개발 범위

### 반드시 구현할 기능

1. 조직·부서·협력 기관과 역할 관리
2. CSV 기반 자산 등록 및 중복 확인
3. 장비별 재원·보조금 문서·사용 조건 기록
4. 대여 요청과 승인·반려 흐름
5. 모바일 웹 QR 인수·반납 체크
6. 사진·서명·시각이 포함된 인수인계 기록
7. 실제 사용 목적·프로그램 코드 기록
8. 대여 건별 PDF/CSV 증빙 내보내기
9. 변경 이력과 사용자 활동 로그

### MVP에서 제외할 기능

- 회계·ERP·자산관리 시스템 전체 교체
- 보조금 규정의 자동 법률 해석
- 자동으로 대여 적격성을 확정하는 AI
- 장비 위치를 추적하는 GPS 하드웨어
- 결제·대여료 청구·보험 중개
- 정부 감사 시스템에 자동 제출하는 기능

## 9. 기술 아키텍처 제안

- **Frontend:** Next.js + TypeScript
- **UI:** Tailwind CSS
- **Backend:** Cloudflare Workers 또는 Supabase Edge Functions
- **Database:** PostgreSQL (Supabase로 MVP 시작)
- **File Storage:** Cloudflare R2 또는 Supabase Storage
- **Authentication:** Supabase Auth
- **QR:** 자산별 고유 식별 URL
- **PDF:** 서버 측 보고서 생성
- **Audit Log:** append-only 이벤트 테이블과 변경 전·후 값 기록
- **Import/Export:** CSV/XLSX 및 PDF

### 데이터 신뢰성 원칙

- 자산·대여·사용·반납 이벤트는 원본 시각과 행위자를 보존한다.
- 보조금 조건은 원문 문서와 담당자가 입력한 요약을 함께 저장한다.
- AI가 사용 조건을 자동 확정하지 않는다.
- 고객 간 데이터 접근을 테넌트·기관 단위로 격리한다.
- 외부 협력 기관은 자신에게 공유된 대여 건만 볼 수 있게 한다.
- 증빙 파일의 보존 기간과 삭제 정책을 고객이 설정할 수 있게 한다.

## 10. 고객 확보 전략

1. 지역정부 보조금 관리자와 자산관리 담당자 인터뷰
2. 지역 비영리 컨소시엄·재난 대응 협력 네트워크 조사
3. 보조금 관리 컨설턴트와 지방정부 자산관리 공급업체를 소개 파트너 후보로 발굴
4. 기존 자산관리 시스템을 쓰는 조직을 대상으로 CSV 가져오기 데모 제공
5. 1개 지역 네트워크에서 30~60일 유료 파일럿 실행
6. 파일럿에서 기관 간 대여 건의 승인·인수·반납 기록 완결성과 담당자 시간 절감 측정

초기에는 광고보다 직접 인터뷰와 좁은 지역 파일럿을 우선한다. 공공기관 판매는 보안·조달 절차로 시간이 길어질 수 있으므로, 빠른 검증을 위해 비영리 컨소시엄이나 민간 프로그램 운영기관도 함께 접촉한다.

## 11. 초기 개발·운영 비용 가설

### MVP 비용

- 개발: 기존 무료·저가 클라우드와 오픈소스 라이브러리로 시작
- DB·파일 저장·인증: 초기 소규모 사용량 기준 월 $30~$150 가정
- 이메일·알림: 사용량에 따라 월 $5~$30 가정
- QR 라벨: 일반 인쇄물로 시작하며 전용 하드웨어는 제외
- AI 비용: MVP 필수 경로에서 제외

위 금액은 공급사 견적이나 실측 비용이 아니라 초기 예산 가설이다. 실제 사용량, 보안 요구, 백업 보존, 파일 다운로드 트래픽을 측정한 후 수정한다.

### 주요 운영 리스크

- **공공 조달 지연:** 구매 승인과 예산 편성에 시간이 걸릴 수 있다. 비영리 네트워크 파일럿으로 초기 판매 주기를 단축한다.
- **다자간 온보딩:** 여러 기관이 계정을 만들고 실제 인수인계에 참여해야 가치가 발생한다. 외부 사용자는 초대 링크와 제한된 권한으로 쉽게 참여하게 한다.
- **기존 시스템 중복:** InventoryGrant·Wasp 또는 고객의 기존 자산관리 시스템이 이미 전체 흐름을 제공할 수 있다. 대체보다 연동을 우선한다.
- **규정 해석 책임:** 보조금 조건을 잘못 설정하면 고객이 잘못된 판단을 할 수 있다. 모든 규칙은 고객 담당자가 확인·승인하고 제품은 기록·알림만 제공한다.
- **개인정보·보안:** 인수자 정보, 기관 연락처, 사진과 서명이 저장될 수 있다. 최소 수집, 접근통제, 암호화, 보존·삭제 정책을 기본으로 한다.
- **사용 빈도 부족:** 장비 대여가 드문 조직은 월 구독료를 지불하지 않을 수 있다. 여러 기관이 자주 장비를 공유하는 네트워크만 우선 타깃으로 삼는다.

## 12. 확장성

초기에는 미국 연방 보조금으로 취득한 장비를 여러 기관이 공유하는 업무에 집중한다.

이후 확장 후보:

1. 지방정부의 여러 부서 간 공용 장비 풀
2. 지역 비영리기관·교육기관 간 공동 자산 운영
3. 공공 안전·지역사회 지원 프로그램의 장비 인수인계
4. 대학 연구시설이 아닌 공공·비영리 공동 장비 네트워크
5. 국가별 공공 보조금·기부 자산 규정에 맞춘 현지화

확장 시 국가별 보조금·자산 처분 규정은 별도로 검토해야 한다. 하나의 규칙을 모든 국가와 기관에 적용하지 않는다.

## 16. 현재 판단

**초기 사업 가설 — 검증 전.**

공공 보조금 장비의 기록·관리에는 실제 규정상 요구사항이 존재하고, 보조금 자산관리 제품과 공유 장비 예약 제품도 이미 판매되고 있다. 따라서 단순 자산 목록이나 예약 캘린더는 차별점이 아니다.

AwardRelay가 성립하려면 **서로 다른 기관 사이에서 장비를 공유하는 과정**에서 요청·승인·인수인계·실제 사용 목적·반납 증빙이 분리되어 있고, 기존 제품으로 이를 충분히 해결하지 못하는 고객이 확인되어야 한다.

가장 큰 미검증 가설은 다음 세 가지다.

1. 기관 간 공유 장비 운영이 월 구독료를 낼 만큼 자주 발생하는가?
2. InventoryGrant·Wasp·기존 자산관리 시스템의 실제 도입 고객에게 남아 있는 기능 공백이 있는가?
3. 보조금 담당자와 자산 담당자가 별도 운영 레이어를 도입할 만큼 증빙 재구성 비용을 크게 느끼는가?

고객 인터뷰와 유료 파일럿 전에는 시장 규모, 경쟁 우위, 지불 의사 또는 규정 준수 효과를 검증된 사실로 주장하지 않는다.
