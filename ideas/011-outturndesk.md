# IDEA-011 — OutturnDesk

> **한 줄 설명:** 생두 수입사와 스페셜티 로스터가 계약 샘플부터 선적·도착 샘플·품질 이의제기까지의 증빙을 한 Lot에 연결하는 B2B SaaS.

**상태:** 초기 사업 가설 — 고객 인터뷰 및 유료 파일럿 전  
**조사 기준일:** 2026-11-17  
**핵심 원칙:** 커피의 품질 합격·불합격이나 계약 위반을 자동 판정하지 않는다. 계약 당사자가 검토할 수 있도록 측정값·원본 자료·샘플 이력·기한을 연결한다.  
**제품명:** OutturnDesk는 작업명이며 상표·도메인 사용 가능 여부는 별도 확인이 필요하다.

---

## 1. 발견한 불편함

생두 거래에서는 구매 전에 확인한 샘플과 실제 도착한 커피의 품질이 다를 수 있다. 계약에 따라 판매 샘플, 선적 전 승인 샘플, 도착 샘플, 중재용 봉인 샘플 등이 사용될 수 있고, 품질 이슈가 생기면 계약서·샘플 기록·선적 자료·검사 결과를 함께 확인해야 한다.

실무 담당자는 다음 자료를 서로 다른 위치에서 관리할 수 있다.

- 매매 계약서와 품질 설명, 허용 범위, 샘플 승인 조건
- 사전 샘플 및 선적 전 샘플의 평가 기록
- 계약 Lot, 컨테이너, 봉인 번호, B/L 및 입고 정보
- 도착 샘플의 수분·수분활성도·밀도·스크린·결점·커핑 결과
- 사진, 외부 검사기관 보고서, 창고·운송 관련 문서
- 공급사와 주고받은 품질 이슈 및 정산·allowance 협의 내역

이 자료가 Lot별로 연결되지 않으면 담당자가 품질 차이를 발견한 뒤 근거를 다시 모으고, 어떤 계약 조건과 기한이 적용되는지 재확인해야 할 수 있다.

**검증할 문제 가설:** 반복적으로 생두를 수입하는 업체 중 일부는 계약 샘플과 도착 품질 증빙을 연결하는 데 시간을 쓰며, 이 과정의 누락이나 지연이 실제 금전적 손실 또는 분쟁 대응 비용으로 이어지는가?

## 2. 문제의 근본 원인

1. 계약, 샘플, 선적, 도착 검사 데이터가 서로 다른 파일·메일·시스템에 저장된다.
2. 샘플 이름과 Lot 번호가 공급사·수입사·창고·검사기관마다 다르게 쓰일 수 있다.
3. 측정값만 남고 측정 시점, 담당자, 장비, 샘플 출처, 봉인 정보가 빠질 수 있다.
4. 품질 기준과 이의제기 절차는 계약 조건과 거래 조건에 따라 달라진다.
5. 품질 담당자와 구매·물류·재무 담당자가 같은 사건의 서로 다른 부분을 관리한다.

위 항목은 시장 전체에 대한 확정 사실이 아니라 고객 인터뷰와 실제 업무 자료로 확인할 가설이다.

### 경쟁 조사 결론

이미 Cropster는 계약 Lot과 샘플 그룹 연결을 제공하고, GiesenCloud는 생두 품질 측정 이력을 관리한다. 따라서 '생두 계약·품질관리 SaaS'를 새 시장이라고 주장하지 않는다.

OutturnDesk의 차별화 가설은 다음의 좁은 연결 업무다.

- Cropster 등 기존 재고·QC 도구를 대체하지 않고 CSV·PDF·이메일 첨부 자료를 받아온다.
- 계약에서 승인한 샘플과 도착 샘플을 동일한 거래 사건에 연결한다.
- 계약·컨테이너·샘플·측정·증빙·협의 이력을 하나의 사건 타임라인으로 구성한다.
- 계약 당사자가 확인한 기한과 요구 자료를 체크리스트로 관리한다.
- 품질 분쟁 시 기존 기록을 다시 수집하지 않고 검토용 증빙 패킷을 내보낸다.

공개 자료 조사만으로 기존 제품이 이 흐름을 전혀 지원하지 않는다고 단정할 수 없다. 특히 Cropster의 계약·샘플 기능과 직접 비교하는 고객 인터뷰가 필수다. 기존 시스템에서 동일한 작업을 충분히 수행하고 있다면 차별성은 성립하지 않는다.

## 4. 제안 제품

### OutturnDesk — Contract-to-Outturn Evidence Workspace

거래 단위로 사건을 만들고 다음 기록을 연결하는 웹 SaaS다.

1. **계약 요약:** 계약번호, 공급사, 구매자, 품종·산지, Lot, 계약 수량, 품질 설명, 샘플 승인 조건, 사용 계약 양식 및 관련 조항.
2. **샘플 이력:** 샘플 유형, 채취·수령 날짜, 채취자·기관, 샘플 ID, 봉인 ID, 사진, 보관·전달 기록.
3. **선적 이력:** 컨테이너, 봉인 번호, B/L, 선적·도착·하역 날짜, 포장·중량 문서.
4. **도착 검사:** 수분, 수분활성도, 밀도, 스크린, 결점, 커핑 결과 등 고객이 사용하는 측정값과 원본 보고서.
5. **차이 검토:** 계약에 적힌 값과 측정값을 나란히 표시하고, 비교 불가·자료 부족·조건 불일치를 별도 표시.
6. **이슈 관리:** 담당자, 확인할 자료, 공급사 질의, 협의 상태, 다음 검토일.
7. **증빙 패킷:** 계약·샘플·선적·검사 자료, 타임라인, 원본 파일 링크와 변경 이력을 PDF/ZIP으로 내보낸다.

AI는 PDF에서 계약번호·날짜·측정값 후보를 추출하는 보조 기능으로만 사용한다. 사용자가 확인하기 전에는 계약 조건, 기한, 측정값을 확정하지 않는다.

## 5. 핵심 사용 흐름

1. 구매 담당자가 계약서와 사전 샘플 기록을 업로드한다.
2. 시스템이 Lot 사건을 만들고, 추출된 계약 조건과 날짜를 사용자에게 확인받는다.
3. 선적·컨테이너·봉인·B/L 정보를 추가하거나 CSV로 가져온다.
4. 창고·품질 담당자가 도착 샘플과 검사 결과를 등록한다.
5. 시스템은 계약 조건과 측정값의 차이 및 누락된 증빙을 보여준다.
6. 사용자가 공급사에 확인할 이슈와 다음 조치를 지정한다.
7. 필요할 때 담당자가 증빙 패킷을 생성해 공급사·검사기관·중재 절차 담당자와 공유한다.

## 6. 타깃 고객과 사용해야 할 이유

### 1차 고객

- 매달 여러 공급사·컨테이너의 생두를 수입하는 생두 수입사·도매상
- 여러 수입사와 계약하며 품질 이력을 관리하는 중대형 스페셜티 로스터
- 구매·품질·물류 담당자가 분리된 커피 업체
- 고객사별 품질 증빙을 제공해야 하는 독립 검사·품질 서비스 업체

### 실제 사용자

- Green Coffee Buyer
- Quality Manager / QC 담당자
- 수입·물류 담당자
- 공급사 품질 이슈를 처리하는 구매·재무 담당자

### 고객이 사용할 이유

- 계약 샘플, 도착 샘플, 검사 결과를 같은 Lot에서 비교할 수 있다.
- 자료를 다시 찾고 이메일을 뒤지는 시간을 줄일 수 있다.
- 누가 어떤 자료를 언제 등록했는지 확인할 수 있다.
- 공급사와 이슈를 논의할 때 원본 근거를 빠르게 전달할 수 있다.
- 담당자 교체 후에도 Lot별 품질 이력이 남는다.

## 7. 지불 고객과 수익 모델 가설

실제 지불 의사는 아직 검증되지 않았다. 구매자는 소비자가 아니라 생두 수입·도매 업체와 반복 수입하는 로스터로 가정한다.

| 플랜 | 월 가격 가설 | 사용 범위 가설 |
|---|---:|---|
| Starter | US$79 | 활성 Lot 10개, 기본 증빙·내보내기 |
| Buyer | US$199 | 활성 Lot 50개, 팀 권한·알림·공급사 공유 |
| Importer | US$399 | 활성 Lot 200개, 다중 팀·CSV 가져오기·감사 로그 |
| Case Pack | US$19/건 | 단일 품질 이슈 증빙 패킷 생성 |

가격은 검증 전 가설이다. 실제 가격은 월 수입 Lot 수, 품질 이슈 빈도, 현재 증빙 정리 시간, 기존 시스템 비용을 인터뷰한 뒤 수정한다.

## 8. MVP 개발 범위

### 반드시 구현할 기능

1. 회사·사용자·권한과 Lot 사건 생성
2. 계약서·PDF·이미지·CSV 업로드
3. 계약 조건과 날짜의 수동 확인 화면
4. 샘플 유형·ID·봉인 ID·담당자·날짜 기록
5. 선적 및 도착 이력 기록
6. 측정값 입력과 계약 기준 비교표
7. 누락 증빙·확인 과제·기한 알림
8. 원본 파일과 타임라인을 포함한 PDF/ZIP 내보내기
9. 사용자별 변경 이력과 데이터 삭제 기능

### MVP에서 제외할 기능

- 자동 품질 합격·불합격 또는 계약 위반 판정
- 자동 중재 신청·법률 문서 제출
- 센서·측정 장비의 실시간 연동
- 모든 LIMS·ERP·Cropster와의 양방향 통합
- 자체 커핑 점수나 품질 등급의 보증
- 블록체인 기반 증명

## 9. 기술 아키텍처 제안

- Frontend: Next.js + TypeScript
- Backend: Cloudflare Workers 또는 Supabase Edge Functions
- Database: PostgreSQL (테넌트·회사·Lot·샘플·검사·이슈 관계)
- File storage: Cloudflare R2 또는 Supabase Storage
- Authentication: Supabase Auth
- Background jobs: 계약·기한 알림, 문서 처리 큐
- PDF: 서버 측 HTML-to-PDF 또는 PDF 라이브러리
- Optional AI: OCR 및 필드 후보 추출. 확정 전 사용자 확인 필수.

### 데이터 무결성 원칙

- 원본 파일을 보존하고 추출값과 원본 페이지·영역을 연결한다.
- 단위, 측정 날짜, 측정자, 장비 및 시험 조건을 가능한 범위에서 함께 저장한다.
- 서로 다른 방법으로 얻은 측정값을 무조건 같은 값처럼 비교하지 않는다.
- 샘플 채취·전달·봉인 기록과 실제 측정 결과를 구분한다.
- 사용자가 수정한 값과 이전 값을 변경 이력으로 남긴다.
- 회사별 접근 권한과 공유 링크 만료·회수 기능을 제공한다.

## 10. 고객 확보 전략

1. 생두 수입사·도매상·중대형 로스터의 구매 및 QC 담당자 10~15명 인터뷰
2. 익명화한 계약서·샘플 기록·도착 검사 자료로 수동 증빙 패킷을 만들어 문제를 검증
3. 커피 품질 검사기관, 창고, 수입 대행사와 소개 파트너십 검토
4. Green Coffee Association 및 커피 무역·품질 관련 네트워크를 통해 파일럿 고객 접촉
5. '계약 샘플에서 도착 검사까지 Lot 증빙을 연결하는 방법'을 주제로 전문 콘텐츠 제작
6. 초기에는 고객 데이터의 무단 사용 없이, 서면 동의를 받은 샘플 자료만 활용

대량 광고보다 실제 거래 자료를 이용한 수동 파일럿이 먼저다.

## 11. 초기 개발·운영 비용과 리스크

### 비용 가설

- MVP 개발: 1인 개발 기준 약 4~6주 가설. 문서 파싱·권한·감사 이력 범위에 따라 달라진다.
- 초기 인프라: 사용량이 적은 동안 월 US$20~100 수준을 목표로 하되, 실제 파일 저장량·이메일·백업 비용을 측정한다.
- AI/OCR: 초기에는 선택 기능으로 제한하고 페이지 수·문서 크기별 비용을 별도 측정한다.
- 주요 변동비: 파일 저장·전송, OCR, 알림 발송, 고객별 데이터 백업 및 지원.

위 수치는 공급사 견적이나 실측 결과가 아닌 초기 계획 가설이다.

### 리스크와 대응

- **계약별 조건 차이:** GCA와 ESCC 등 서로 다른 계약 양식이 존재한다. 계약 양식·판본·서명된 특약을 사용자가 확인하고, 시스템은 확인된 날짜와 조항만 추적한다.
- **기한 계산 오류:** 시스템이 법률상 권리나 제출 가능 여부를 판단하지 않는다. 계약서와 상대방·전문가 확인을 거친 기한을 사용자가 승인하도록 한다.
- **샘플 대표성:** 등록된 사진이나 측정값이 컨테이너 전체를 대표한다고 보장하지 않는다. 채취 주체·방법·시점·봉인 상태를 구분하고, 필요한 경우 독립 기관의 샘플링 자료를 연결한다.
- **측정 방법 차이:** 장비·시험방법·단위·조건이 다르면 수치 비교가 부정확할 수 있다. 비교 조건이 다르거나 불명확하면 자동 점수화하지 않는다.
- **기존 제품의 기능 중복:** Cropster의 계약·샘플 연결과 QC 시스템이 이미 충분할 수 있다. 실제 사용 중인 기능과 남는 업무를 고객별로 확인한다.
- **분쟁 책임:** 제품은 증빙 정리 도구이지 품질 인증기관·중재기관·법률 자문 서비스가 아니다. 결과물에 원본 출처와 사용자 확인 상태를 표시한다.
- **기밀성:** 가격·공급사·계약·검사 데이터는 민감할 수 있다. 최소 수집, 암호화, 회사별 분리, 접근 기록, 삭제·내보내기를 제공한다.
- **시장 규모와 구매 빈도:** 품질 이슈가 드물거나 기존 업무가 충분히 정리된 업체는 유료 고객이 아닐 수 있다. 활성 Lot 수와 실제 문제 발생 빈도를 기준으로 고객군을 좁힌다.

## 12. 30일 시장 검증 계획

### 1~7일: 문제 인터뷰

- 생두 수입사·도매상·로스터 10~15명 인터뷰
- 최근 12개월의 샘플-도착 품질 차이 경험과 대응 절차 질문
- 실제로 어떤 자료를 어디에서 찾는지 확인
- Cropster 등 기존 제품에서 이미 처리하는 업무와 수작업으로 남는 업무 구분

### 8~14일: 수동 파일럿

- 동의받은 익명화 자료로 3개 Lot의 사건 타임라인을 수동 구성
- 계약·샘플·도착 검사·선적 자료를 연결
- 기존 방식과 비교해 증빙 정리 시간, 누락 자료, 사용자 만족도 측정

### 15~23일: MVP 프로토타입

- Lot 생성, 파일 업로드, 샘플 기록, 검사값 비교, 이슈 목록, PDF 패킷 구현
- 파일럿 고객 2~3곳에서 업무 흐름 확인
- AI 추출 없이도 제품 가치가 있는지 검증

### 24~30일: 유료 의사 확인

- US$79 / US$199 가격 가설 제시
- 무료 사용 의향이 아니라 유료 파일럿 또는 구매 의향 확인
- 도입을 거부하는 이유와 기존 시스템 대체 비용 기록

### 진행 기준 가설

- 인터뷰 10곳 중 4곳 이상이 최근 12개월에 반복적인 증빙 수집·품질 이슈 대응 문제를 보고
- 3곳 이상이 익명화된 샘플 자료로 파일럿 진행에 동의
- 2곳 이상이 월 구독 또는 Lot별 패킷에 실제 비용을 지불할 의사를 보임

기준을 충족하지 못하거나 기존 제품의 기능으로 문제가 이미 해결된다면 개발을 중단하거나 고객군을 재설정한다.

## 13. 검증 지표

- Lot 1건의 증빙 패킷을 완성하는 데 걸리는 시간
- 계약·샘플·도착 검사 자료의 연결 성공률
- 필수 자료 누락률
- OCR 추출값의 사용자 수정률
- 기존 시스템으로 해결되지 않은 업무 비중
- 파일럿 고객의 주간 활성 Lot 수
- 유료 파일럿 전환율 및 3개월 유지율
- 품질 이슈 1건당 담당자의 자료 수집 시간

품질 클레임의 승소율이나 회수 금액을 제품 성과로 과장하지 않는다. 거래 결과는 계약·샘플링·협상 등 여러 요인의 영향을 받는다.

## 14. 최종 사업성 평가

| 항목 | 현재 판단 |
|---|---|
| 문제의 실재 가능성 | 중간 — 실제 거래 자료와 인터뷰 필요 |
| 지불 의사 | 미검증 |
| 경쟁 강도 | 중간~높음 — Cropster 등 인접 기능 존재 |
| 기술적 MVP 난이도 | 중간 |
| 초기 자본 요구 | 낮음~중간 |
| 글로벌 확장성 | 중간 — 커피 거래 관행·계약 양식·언어 차이 |
| 차별성 | 미검증 — 기존 QC·재고 도구를 잇는 증빙 사건 관리 |
| 현재 결정 | 고객 인터뷰 전 조건부 검토 |

**결론:** OutturnDesk는 생두 재고나 품질 측정 시스템을 새로 만드는 아이디어가 아니다. 기존 도구가 관리하는 계약·샘플·QC 자료를 거래별 품질 이슈와 증빙 패킷으로 연결하는 좁은 업무를 제안한다. Cropster의 기존 기능과 차별성이 충분하지 않으면 진행하지 않는다. 시장 규모, 수요, 가격, 수익성은 아직 검증되지 않았다.
